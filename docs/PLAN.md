작성: 2026-08-20 · 상태: **승인 대기**

## 1. 스택 결정 (제안)

| 항목 | 결정 | 근거 |
|---|---|---|
| Phase 2 스택 | **Electron + FullCalendar(MIT)** | 캘린더 뷰(드래그·리사이즈·스냅·일/주/월/연)가 라이브러리로 제공, 반투명·프레임리스·트레이·글로벌 단축키 모두 성숙한 API. 많은 iteration에 최적 |
| 런타임 | Node v24 (설치 확인됨) | Python은 3.8로 오래됨 |
| 데이터 | 기존 `%APPDATA%\TodoPopup\` GCal 호환 JSON **그대로 공유** | C# v1과 호환, 추후 C# 포팅 시 데이터 이동 없음 |
| C# v1 | 저장소에 유지 | 초경량(50KB)·폐쇄망 레퍼런스. UI 스펙의 기준 구현 |
| 추후 C# 포팅 | P4에서 재평가 | UI가 웹이므로 WebView2 호스트 포팅이 유력 경로 |

트레이드오프: Electron은 배포 ~90MB·RAM ~200MB로 무겁다. "가장 가벼운 것" 요구는 P4 C# 포팅에서 회수한다.

### 반복(Recurrence)
GCal `recurrence` 필드(RRULE) 형식 그대로 저장한다.
- **구현**: FREQ=DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL, BYDAY(매주 월·수 등), BYMONTHDAY, UNTIL, COUNT, EXDATE(이 일정만 삭제)
- **구현**: 반복 수정 범위 "이 일정만 / 전체"
- 후순위: "이후 모든 일정", BYSETPOS(둘째 화요일) — 폼에서는 미노출, 데이터는 보존
- 미구현: RDATE

## 3. Phase 2 세부 (이번 구현, Electron)

### P2-1 코어 이식 + 신규 소요구
- 트레이 아이콘(파란 원+흰 체크)과 **동일한 아이콘을 창 타이틀바·작업표시줄·exe에 적용**
- 팝업: v1 스펙 그대로(위치 프리셋/크기/투명도/드래그/확인·N분 뒤·완료·취소/무한 반복/빈 슬롯 스택/포커스 안 뺏음)
- **N분 전 미리 알림**: 이벤트별 `reminders.overrides[{method:"popup", minutes:N}]` 다중. 미리 알림 팝업은 "예정 알림" 표기로 구분, 재알림 반복은 정시 알림에만 적용(기본), 옵션으로 미리 알림도 반복
- 목록 창: 폭 축소(≈420px), 자연어 입력+칩+상세 버튼
- 설정 기본값 변경: **자동 실행 ON**, **지난 항목 표시 ON** (설치 첫 실행 시 적용)
- **글로벌 단축키**(변경 가능): 목록 열기 `Ctrl+Alt+T`, 새 일정 입력 `Ctrl+Alt+N`
- 단일 인스턴스, 기존 todos.json 그대로 로드

### P2-2 캘린더 뷰
- FullCalendar: 일/주/월/연 전환(단축키 1~4), 오늘 이동(t)
- 창 기본 **반투명**(기본 90%, 30~100% 조절, 포커스 시 불투명 옵션)
- 드래그 이동·리사이즈 스냅 **N분(기본 15, 설정)**
- **복사/붙여넣기**(Ctrl+C/V — 선택 이벤트를 클립보드에, 붙여넣기는 커서 시각), 복제, 빈 슬롯 클릭·드래그로 생성
- 이벤트 클릭 → 요약 카드, 더블클릭 → 상세 폼

### P2-3 상세 등록 폼
제목 / 날짜·시간(시작·종료) / 종일 / 반복(프리셋+커스텀) / 미리 알림 다중 / 색상 / 설명 / 위치 / 재알림 간격(우리 고유)

### P2-4 반복 전개 엔진
RRULE 서브셋 전개(뷰 범위 내 lazy 전개), 완료/스누즈는 인스턴스(날짜) 단위로 오버레이 — 원본 이벤트 오염 없음(P3 통합 계층과 같은 원리)

## 4. 캘린더 사이드바 (P2에 편입, 구현됨)

캘린더 뷰 좌측에 GCal식 사이드바: 서비스 → 계정 → 캘린더 트리.
캘린더별 [표시 체크박스] [색상 지정(팔레트 14색+직접 지정)] [알람 켬/끔] [이름 변경/삭제].
로컬 계정(그룹)·캘린더는 사이드바에서 즉시 추가. 데이터는 `calendars.json`
(GCal `calendarList` 스키마: `summary`/`backgroundColor`/`selected`/`accessRole`/`primary`),
이벤트의 소속은 `extendedProperties.private.calendarId`.
이벤트 색 규칙 = GCal과 동일: 이벤트 `colorId`가 있으면 그것, 없으면 캘린더 색.
표시 끔 = 뷰·목록에서 제외(알람은 유지), 알람 끔 = 캘린더 단위로 팝업 중지.

## 5. 계정·캘린더 추가 UX — 벤치마크와 제안 (2026-08-20)

### 벤치마크
| 제품 | 추가 흐름 |
|---|---|
| 구글 캘린더 웹 | 사이드바 "다른 캘린더 +" 메뉴: ①새 캘린더 만들기(이름·설명) ②구독(이메일) ③URL로 추가(iCal, 읽기전용) ④가져오기(ICS/CSV를 기존 캘린더에 병합) ⑤관심분야(공휴일 등). 계정 전환은 캘린더 밖(프로필). |
| Outlook/Thunderbird/Apple | "계정 추가" 마법사: 유형 선택(Google/Exchange/CalDAV/ICS) → 인증(브라우저 OAuth 또는 서버주소+자격증명) → 가져올 캘린더 체크 → 색·표시 설정 → 사이드바에 계정 그룹으로 표시. 계정 헤더에서 재인증·새로고침·제거. |
| 공통 패턴 | (1) "캘린더 만들기"와 "계정 연결"은 별개 흐름 (2) 연결 직후 캘린더 단위 선택·색·알림 설정 (3) 읽기전용은 '구독'으로 구분 표시 |

### 제안 — 사이드바 하단 "+ 추가" 단일 진입점, 유형만 다른 공통 마법사
모든 유형(로컬 포함)이 같은 다이얼로그 골격을 쓴다: **유형 선택 → 유형별 폼 → 캘린더 선택·정책 → 완료**.

1. **새 캘린더**: 대상 계정 선택(create 능력이 있는 계정만 노출, 로컬 포함) + 이름 + 색. 로컬은 즉시 생성. *(구현됨: 계정 헤더 ＋ 버튼, 하단 로컬 계정 추가)*
2. **계정 연결**: 유형 목록에서 선택 —
   - 로컬(그룹): 인증 없음, 이름만. *(구현됨)*
   - Google: OAuth 루프백(기본 브라우저 열림) → 성공 시 calendarList 조회 → **가져올 캘린더 체크리스트**: 캘린더별 [표시] [알람] [원격 반영(쓰기 능력 있을 때만 활성)] + 색 → 완료. *(P3)*
   - CalDAV: 서버 URL + 계정/비밀번호 → 캘린더 목록 조회 → 동일 체크리스트. *(P3)*
   - 사내 API: 어댑터가 선언한 폼(URL·토큰 등) → 능력은 어댑터 선언대로(대부분 읽기전용). *(P3, 스펙 수령 후)*
3. **구독(URL/파일)**: ICS 주소나 파일 경로 + 갱신 주기 → 계정 없는 "구독" 그룹에 읽기전용 캘린더로 추가. *(P3)*

부가: 캘린더 우클릭 → **ICS 가져오기**(파일을 해당 캘린더에 병합; 폐쇄망 이관용) / **내보내기**(ICS·JSON). 계정 헤더 메뉴 → 재인증·캘린더 다시 불러오기·계정 제거(로컬 캐시 삭제 여부 확인).

정책 규칙은 기존 설계 그대로: 동작 = 능력(capability, 어댑터 선언) AND 정책(policy, 사용자 토글). 폐쇄망은 로컬+파일 구독만으로 완전 동작.

## 6. P3 — 캘린더 계정 연결 (다음 단계)

진입점은 캘린더 창 사이드바 하단 **"＋ 캘린더 추가…"** 하나로 모았다(구현됨).
메뉴: 새 캘린더 · 계정(그룹) 추가 — 지금 동작 / ICS 구독 · Google 연결 — "준비 중" 으로 표시.
메뉴에 없으면 "이 앱은 못 한다"로 읽히고, 있는 척하면 눌러도 아무 일이 없다. 그래서 둘 다 피한다.

순서와 이유:
1. **ICS 구독(읽기 전용)** — 가장 작고, 폐쇄망에서도 파일로 쓸 수 있다. URL 또는 로컬 `.ics`,
   갱신 주기 설정, `accessRole: reader` 로 등록해 편집·생성 대상에서 자동 제외.
   네트워크는 새 관문 `app/main/calendars/` 안에서만(lint:network 에 관문 추가).
2. **Google 캘린더(CRUD)** — OAuth 루프백. client id 는 사용자가 Google Cloud Console 에서
   만들어 설정에 넣는다(앱에 비밀키를 박지 않는다). calendarList 조회 → 가져올 캘린더 체크 →
   캘린더별 [표시] [알람] [원격 반영]. 토큰은 safeStorage 암호화.
3. **CalDAV** — 사내 서버용. 스펙 확인 후.

**구분(사용자 확인)**: 구글 계정 로그인은 *데이터 소스*와 무관하다. 웹 버전에서 계정별 저장소를
가르는 **신원 확인 용도**이며, 구글 캘린더를 기본 저장소로 쓰는 것이 아니다.
로컬 저장이 언제나 기본이고, 구글 캘린더 연동은 켜야만 동작하는 옵션이다.

## 7. P5 — 웹 버전 (옵션, 로컬이 기본)

지금 구조가 이미 웹을 향해 있다: 창 코드는 평범한 HTML/JS 이고 `window.api` 관문 하나로만
main 과 이야기한다. 그 관문을 HTTP 호출로 바꾸면 같은 화면이 브라우저에서 돈다.
`shared/contracts.js`·`registry.js` 는 UMD 라 브라우저에서 그대로 로드된다.

| | 데스크톱(기본) | 웹(옵션) |
|---|---|---|
| 저장 | `%APPDATA%\TodoPopup` | 서버, **구글 계정별 격리** |
| 알림 | 트레이 팝업·무한 재알림 | 탭이 열려 있을 때만 브라우저 알림 — 알림은 데스크톱이 담당 |
| 로그인 | 없음(로컬) | 구글 로그인 — **저장소 격리 용도** |
| 배포 | `start-todo.bat` / exe | `_global` frontend 서비스 + 기존 8850 API 쌍 |

방향: 프론트엔드 서비스(예: 8851)를 따로 등록해 8850 API 를 부르게 한다
(`_global` 의 security-rdp 8898/8897 쌍과 같은 관례). 사용자 식별은 구글 OIDC 로 받고,
`x-global-user` 대신 검증된 구글 sub 로 상태 파일을 가른다.
